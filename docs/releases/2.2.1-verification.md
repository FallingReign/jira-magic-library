## Remaining integration failure

`manifest-storage.test.ts` expects a manifest to disappear after its two-second TTL. The v2.2.0 cache marks it stale after two seconds and retains the value; physical expiry is seven days. `ManifestStorage` uses that existing default. Both runtime files are unchanged.

**Proposed test-only correction, awaiting the user's answer:** verify the configured freshness period and retained stale value, without changing cache behavior. Replace the expired-is-null expectation with:

```ts
const stale = await redisCache.get(`bulk:manifest:${manifestId}`);
expect(stale.isStale).toBe(true);
expect(JSON.parse(stale.value!)).toEqual(manifest);
expect(await shortTtlStorage.getManifest(manifestId)).toEqual(manifest);
expect(await redisCache.get(`bulk:manifest:${manifestId}`, { rejectStale: true }))
  .toEqual({ value: null, isStale: false });
```

Also verify `isStale: false` before the wait and name the test around freshness/retention. These assertions have **not** been applied. After the decision, rerun the complete integration suite before publishing.

The hierarchy progress test earlier observed a final callback of 2/3 despite three successful creates; it passed on the latest full run. Its assertion and library behavior remain unchanged. Treat the earlier observation as an intermittent baseline issue, not a fix included in 2.2.1.
