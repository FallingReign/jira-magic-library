## Compatibility test corrections

`manifest-storage.test.ts` now verifies the existing v2.2.0 cache behavior: a manifest becomes stale after its configured freshness period and remains available for retry. Explicit `rejectStale` callers receive a cache miss. The cache and manifest runtime files are unchanged; physical expiry remains seven days.

The test checks freshness before the wait, then asserts:

```ts
const stale = await redisCache.get(`bulk:manifest:${manifestId}`);
expect(stale.isStale).toBe(true);
expect(JSON.parse(stale.value!)).toEqual(manifest);
expect(await shortTtlStorage.getManifest(manifestId)).toEqual(manifest);
expect(await redisCache.get(`bulk:manifest:${manifestId}`, { rejectStale: true }))
  .toEqual({ value: null, isStale: false });
```

The hierarchy progress test now checks periodic Jira search snapshots separately from the final create response. A search snapshot can precede Jira indexing the last issue. Every snapshot must have the correct total and a valid completed count; the final response must report three unique successful issues and zero failures. No final callback, timer change, or new progress behavior was added to the library.
