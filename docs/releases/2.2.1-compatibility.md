# JML 2.2.1 compatibility patch

**Status: verified compatibility release.** See the [verification report](2.2.1-verification.md).

## Decisions

- **D1:** Built from the exact 2.2.0 release commit, `908e5eaf8f8fba4b9f8ae8600da25b49cec909e5`.
- **D2:** Fix scalar Time Tracking requests, blank Sprint selections, and escaping in quoted text and multiline blocks.
- **D3:** Preserve all other 2.2.0 behavior. Automatic quote repair remains enabled; trimming and Unicode cleanup remain; other blank fields are not newly omitted; duplicate fields, authentication, preview and public response formats keep their existing behavior. Jira owns validation of submitted issues. Existing explicit validation APIs are unchanged.

## Fixed requests

Both YAML values below produce `"timetracking": { "originalEstimate": "1d" }` in the Jira request:

```yaml
timeTracking: 1d
```

```yaml
timeTracking: "1d"
```

Nested estimates and the `Original Estimate` / `Remaining Estimate` fields remain supported. The standalone duration converter retains its existing return value; scalar wrapping happens when preparing issue fields.

Blank Sprint values (`null`, an empty string, or whitespace) are omitted. A supplied Sprint remains supported. This fix does not remove other blank optional fields or add local required-field checks.

Existing automatic quote repair remains active. Already-escaped quotes and backslashes no longer receive an extra escaping pass. Other legacy quote-repair rules remain, including literal handling of backslash-n and backslash-t in ordinary pasted quoted values. Use actual multiline blocks for descriptions:

```text
{
  "Project": "TEST",
  "Issue Type": "Task",
  "Summary": "Example",
  "timeTracking": { "originalEstimate": "1d" },
  "Sprint": "",
  "Description": <<<
The user said "broken".
Path: C:\work\file

Keep this internal blank line.
>>>
}
```

Quoted block wrappers remain supported. The existing trimming and Unicode cleanup still apply after parsing. No application-side parser or new configuration flag is required.

## Release handling

The published **3.0.0 tag remains unchanged**. It is unsuitable for this compatibility upgrade because it changes parsing defaults and other public behavior. Applications upgrading from 2.2.0 should pin the verified 2.2.1 tag:

```json
"jira-magic-library": "github:FallingReign/jira-magic-library#v2.2.1"
```

For Jira Tools, change the dependency and lockfile only. Continue sending `{ data, format }` unchanged, with only the existing `yml` format alias conversion. No authentication or preview migration is required.

## Verification

Release requires the complete active JML unit and integration suites, the unchanged coverage thresholds, live Jira create-and-readback checks, and the Jira Tools suite using the packaged patch. The request regression tests inspect the serialized HTTP POST body.

`scripts/acceptance-2.2.1.mjs --live` creates test issues and verifies their final requests and saved fields. It uses `.env.test` and leaves those issues available for inspection.
